1. How These Examples Are Built

Every example follows one rule:

\[ \boxed{ \text{do the native mathematics first} \longrightarrow \text{identify only the BM structure actually required}. } \]

A simple calculation should remain simple. BM structure is activated when the problem contains mathematically relevant distinctions involving:

  • different mathematical sectors;
  • different domains or admissibility conditions;
  • information loss;
  • multiple Tasks;
  • Interfaces;
  • parallel paths;
  • global realization;
  • feedback;
  • law/regime dependence;
  • receiver-relative reuse;
  • repair or obstruction.
The examples do not force every scalar, intermediate expression, parameter, or formula into a separate Branch.

5. Level 1 — Branches and Derived Quantities

Example 1 — Derived Expressions Are Not Automatically Branches
Main idea: Branch essentiality · no Branch explosion

Let

\[ x\in\mathbb R. \]

Compute:

\[ x^2, \qquad x^3, \qquad \sin x. \]

Suppose every downstream Task can be computed from \(x\) itself. Then:

\[ x^2=f_2(x), \qquad x^3=f_3(x), \qquad \sin x=f_4(x). \]

No required mathematical obligation needs these expressions to carry separate native laws, Interfaces, continuation states, or Passports.

Therefore the natural BM reading is:

\[ \boxed{ B_x \quad\text{with derived Leaves}\quad L_{x^2}, L_{x^3}, L_{\sin x}. } \]
Different formulas do not automatically mean different Branches.
Example 2 — Power → Energy → Temperature Leaves
Main idea: Interaction · Leaf · lawful downstream use

Consider:

\[ V=24\text{ V}, \qquad I=5\text{ A}. \]

Electrical Interaction

\[ P=VI. \]
\[ P=(24)(5)=120\text{ W}. \]

Retain power as a Leaf:

\[ \boxed{ L_P=120\text{ W}. } \]

Energy calculation

Let

\[ t=30\text{ s}. \]
\[ E=L_Pt. \]
\[ E=(120)(30)=3600\text{ J}. \]

Retain:

\[ \boxed{ L_E=3600\text{ J}. } \]

Thermal calculation

Let

\[ C_{\mathrm{th}} = 900\text{ J/K}. \]
\[ \Delta T = \frac{E}{C_{\mathrm{th}}} = \frac{3600}{900} = 4\text{ K}. \]
\[ \boxed{ L_{\Delta T} = 4\text{ K}. } \]

BM does not need to declare \(P\), \(E\), and \(\Delta T\) three new Branches merely because they are different quantities. They can remain derived Leaves unless later mathematics requires separate Branch status.

6. Level 2 — Passport Sufficiency

Example 3 — Exact Passport Fibre Audit
Main idea: fibres · exact Task sufficiency

Let

\[ X=\{a,b,c,d\}. \]

Define representation

\[ r(a)=r(b)=0, \qquad r(c)=r(d)=1. \]

The fibres are:

\[ r^{-1}(0)=\{a,b\}, \qquad r^{-1}(1)=\{c,d\}. \]

Task 1

\[ T_1(a)=T_1(b)=7, \qquad T_1(c)=T_1(d)=9. \]

\(T_1\) is constant on every fibre.

\[ \widetilde T_1(0)=7, \qquad \widetilde T_1(1)=9. \]
\[ \boxed{ T_1 = \widetilde T_1 \circ r. } \]

So the representation is exactly sufficient for \(T_1\).

Task 2

\[ T_2(a)=0, \qquad T_2(b)=1. \]

But:

\[ r(a)=r(b) \]

while

\[ T_2(a)\neq T_2(b). \]

Therefore:

\[ \boxed{ T_2 \text{ does not factor through }r. } \]
The same representation can be sufficient for one Task and insufficient for another.
Example 4 — One Representation, Multiple Tasks
Main idea: problem scope · joint obligation family

Let

\[ x=(T,H,P), \]

representing temperature, humidity, and pressure.

Suppose representation

\[ r(x)=(T,H) \]

is retained.

Tasks:

\[ T_A(x) = \mathbf 1_{T>30}, \]
\[ T_B(x) = \mathbf 1_{H>80}. \]

Both factor through \(r\).

Add:

\[ T_C(x)=P. \]

The enlarged obligation tuple is

\[ \mathcal T(x) = \left( \mathbf 1_{T>30}, \mathbf 1_{H>80}, P \right). \]

Now \(r(x)=(T,H)\) is insufficient because pressure has been discarded.

\[ \boxed{ \text{expanded scope} \Rightarrow \text{stronger Passport requirements}. } \]

7. Level 3 — Scope and Branch Essentiality

Example 5 — Scope Changes Branch Essentiality
Main idea: present Task vs future continuation

Let the state be

\[ (x,y)\in\mathbb R^2. \]

Current observation:

\[ R(x,y)=x. \]

Present-only scope

If the only Task is

\[ T_0(x,y)=x, \]

then \(y\) is unnecessary for that scope.

Add future continuation

Let

\[ \Phi(x,y) = (x+y,y). \]

The next observed state is:

\[ R(\Phi(x,y)) = x+y. \]

Compare:

\[ (x,y)=(0,1), \qquad (x',y')=(0,2). \]

Current representations agree:

\[ R(0,1) = R(0,2) = 0. \]

Future representations differ:

\[ R(\Phi(0,1))=1, \qquad R(\Phi(0,2))=2. \]

Therefore \(y\) is redundant for the present-only scope but essential for the continuation scope.

\[ \boxed{ \operatorname{Redundant}_{\mathfrak S_0}(y) \quad\text{but}\quad \operatorname{Essential}_{\mathfrak S_1}(y). } \]

8. Level 4 — Typed Composition

Example 6 — Composition Shrinks the Domain
Main idea: true composite domain

Let

\[ f: [0,\infty) \to [0,\infty), \qquad f(x)=\sqrt x, \]

and

\[ g: (0,\infty) \to \mathbb R, \qquad g(y)=\log y. \]

Then

\[ (g\circ f)(x) = \log\sqrt x. \]

But the true domain is:

\[ D_{g\circ f} = \{ x\ge0: \sqrt x>0 \}. \]
\[ \boxed{ D_{g\circ f} = (0,\infty). } \]

\(f(0)=0\) exists, but \(g(0)\) does not.

Algebraic writability does not override the downstream Operation domain.

9. Level 5 — Parallel Paths and Coherence

Example 7 — Celsius to Kelvin by Two Paths
Main idea: legitimate comparison · exact path coherence

Start with:

\[ T_C=20^\circ\mathrm C. \]

Path 1 — direct

\[ T_K = 20+273.15 = 293.15\text{ K}. \]

Path 2 — through Fahrenheit

\[ T_F = \frac95(20)+32 = 68^\circ\mathrm F. \]
\[ T_K = \frac59(68-32)+273.15 = 293.15\text{ K}. \]

Both outputs already lie in the same comparison space: Kelvin.

\[ \boxed{ F_{\mathrm{direct}}(20) = F_{\mathrm{via}\ F}(20). } \]

This is genuine path coherence.

If the outputs lived in different spaces, a legitimate comparison map would have to be declared first.

10. Level 6 — Configuration, Tree, and Global Realization

Example 8 — Configuration Is Not Yet a Tree
Main idea: candidate specification vs selected realization

Consider one variable \(x\) with candidate constraints:

\[ x=0, \qquad x=1. \]

These constraints can be placed inside a candidate Configuration \(C\).

But:

\[ \mathfrak F(C) = \varnothing. \]

Therefore no lawful realization exists.

\[ \boxed{ \text{Configuration exists} \not\Rightarrow \text{Tree exists}. } \]

A Tree requires:

\[ \xi \in \mathfrak F(C). \]
Example 9 — Local Does Not Imply Global
Main idea: higher coherence · obstruction

Let

\[ a,b,c \in \{0,1\}. \]

Require:

\[ a=b, \qquad b=c, \qquad a\neq c. \]

Each individual condition is satisfiable.

Every pair is also satisfiable.

But the whole set is not:

\[ a=b \land b=c \Longrightarrow a=c, \]

contradicting:

\[ a\neq c. \]

Therefore:

\[ \boxed{ \mathfrak F(C) = \varnothing. } \]
\[ \boxed{ \text{pairwise/local compatibility} \not\Rightarrow \text{global realization}. } \]

11. Level 7 — Law Space

Example 10 — Law Space Earns Separate Status
Main idea: regime-dependent continuation

Let

\[ x=1, \qquad \lambda \in \{0,1\}. \]

Define:

\[ \Phi^{(0)}(x)=x, \]
\[ \Phi^{(1)}(x)=2x. \]

If representation keeps only \(x\), then the visible state \(x=1\) admits two different continuations:

\[ 1 \longmapsto 1 \]

or

\[ 1 \longmapsto 2. \]

Therefore active law/regime information is essential to the continuation scope.

\[ \boxed{ (x,\lambda) \text{ is required for autonomous continuation}. } \]
Example 11 — Law Space Does Not Always Need Separate Branch Status
Main idea: no mandatory law Branch

Suppose:

\[ \lambda=\lambda_0 \]

is fixed throughout the entire problem.

No Operation changes it, no receiver asks for it, and no continuation ambiguity depends on it.

Then \(\lambda_0\) can remain a parameter inside another Branch.

\[ \boxed{ \text{Law Space available} \not\Rightarrow \text{separate Law Branch required}. } \]

12. Dynamic Closure

Example 12 — Static Sufficiency but Dynamic Failure
Main idea: Dynamic Closure

Let:

\[ R(x)=|x|. \]

Consider dynamics:

\[ \Phi(x)=x+1. \]

States:

\[ x=1, \qquad x'=-1 \]

share:

\[ R(1) = R(-1) = 1. \]

But after evolution:

\[ R(\Phi(1)) = |2| = 2, \]
\[ R(\Phi(-1)) = |0| = 0. \]

Therefore no map

\[ \widetilde\Phi: R(\mathbb R) \to R(\mathbb R) \]

can satisfy:

\[ R\circ\Phi = \widetilde\Phi \circ R. \]
\[ \boxed{ \text{Dynamic Closure fails}. } \]
Example 13 — Dynamic Closure Success
Main idea: reduced dynamics on realized image

Keep:

\[ R(x)=|x|. \]

but change dynamics to:

\[ \Phi(x)=2x. \]

Then:

\[ R(\Phi(x)) = |2x| = 2|x|. \]

Define:

\[ \widetilde\Phi(r)=2r, \qquad r\in[0,\infty). \]

Therefore:

\[ \boxed{ R\circ\Phi = \widetilde\Phi \circ R. } \]

The reduced state space is the realized image:

\[ R(\mathbb R) = [0,\infty). \]

13. Defect and Repair

Example 14 — Repair an Insufficient Representation
Main idea: admissible information repair

Let:

\[ X = \mathbb R^2, \qquad F(x,y)=x. \]

Task:

\[ T(x,y)=x+y. \]

\(F\) is insufficient because:

\[ F(0,1) = F(0,2) = 0 \]

but:

\[ T(0,1)=1, \qquad T(0,2)=2. \]

Add repair writer:

\[ q(x,y)=y. \]

The repaired representation is:

\[ (F,q)(x,y) = (x,y). \]

Now:

\[ \widehat T(u,v)=u+v \]

gives:

\[ \boxed{ T = \widehat T \circ (F,q). } \]
This is a successful repair only if adding \(q\) belongs to the declared admissible repair class.
Example 15 — Repair Revalidation in a Cycle
Main idea: semantic dependency closure

Suppose:

\[ x_{n+1}=y_n, \]
\[ y_{n+1}=z_n, \]
\[ z_{n+1}=x_n. \]

The dependency structure contains:

\[ x \to y \to z \to x. \]

Repairing \(x\) affects the entire strongly connected component.

\[ \boxed{ \operatorname{Cl}_{\mathfrak D_C} (\{x\}) = \{x,y,z\}. } \]

Existing certificates for all three variables require revalidation unless an invariance theorem proves otherwise.

14. Response, Export, Root, and Re-entry

Example 16 — Root Receiver Relativity
Main idea: Root is a receiver-relative role

Let:

\[ r=8. \]

Receiver \(B_1\) accepts:

\[ A_R(B_1) = [0,10]. \]

Receiver \(B_2\) accepts:

\[ A_R(B_2) = [0,5]. \]

Therefore:

\[ \boxed{ 8 \text{ is Root for }B_1 } \]

but:

\[ \boxed{ 8 \text{ is not Root for }B_2. } \]
Example 17 — Roothood Is Not Transitive
Main idea: later receivers may require information discarded earlier

Suppose Tree Response:

\[ Y=(x,y). \]

Receiver \(B_1\) requires only:

\[ T_1(x,y)=x. \]

Export:

\[ E_1(x,y)=x \]

is sufficient for \(B_1\).

A later receiver \(B_2\) requires:

\[ T_2(x,y)=x+y. \]

The previous Root value \(x\) cannot reconstruct \(x+y\).

\[ \boxed{ \text{Root for }B_1 \not\Rightarrow \text{Root for }B_2. } \]
Example 18 — Root Reuse Is Not Rooting
Main idea: ordinary downstream use vs candidate attachment

Suppose:

\[ r=4 \]

has already passed its receiver Passport.

The next Operation is:

\[ G: [0,\infty) \to [0,\infty), \qquad G(r)=\sqrt r. \]

Then:

\[ G(4)=2. \]

This is ordinary lawful downstream Root reuse.

\[ \boxed{ \text{No Rooting structure is required}. } \]

Rooting would require an independently defined attachment Operation.

15. Stochastic and Mixed Semantics

Example 19 — Coarse-State Markov Closure Fails
Main idea: stochastic lumpability

Consider states:

\[ X=\{1,2,3\}. \]

Coarsen:

\[ R(1)=R(2)=A, \qquad R(3)=B. \]

Suppose:

\[ K(1,3)=0.1, \qquad K(2,3)=0.9. \]

States \(1\) and \(2\) share the same coarse state \(A\), but their one-step probabilities of entering coarse state \(B\) differ.

\[ 0.1 \neq 0.9. \]

Therefore no Markov transition probability from \(A\) to \(B\) can be determined by the coarse state alone.

\[ \boxed{ \text{coarse Markov Dynamic Closure fails}. } \]
The correct mathematics is lumpability, not deterministic factorization.
Example 20 — Deterministic + Stochastic + Relational Chain
Main idea: sector firewall

Let true binary state:

\[ x\in\{0,1\}. \]

Deterministic preprocessing

\[ f(x)=x. \]

Stochastic sensor

\[ K = \begin{pmatrix} 0.9 & 0.1\\ 0.2 & 0.8 \end{pmatrix}. \]

The output is a probability law.

Nondeterministic decision relation

\[ R(0) = \{\mathrm{wait}\}, \]
\[ R(1) = \{\mathrm{act},\mathrm{wait}\}. \]

The chain contains:

\[ \boxed{ \text{function} \to \text{kernel} \to \text{relation}. } \]

Writing one ordinary expression such as

\[ R(K(f(x))) \]

without declaring the semantic transformations between stages would be mathematically incomplete.

16. Structured Quotients and Witness Scope

Example 21 — A Set Quotient That Does Not Preserve an Operation
Main idea: structured quotient

Let \(X=\mathbb Z\) and define equivalence:

\[ x\sim y \iff |x|=|y|. \]

Thus:

\[ 1\sim -1. \]

Consider ordinary addition.

We also have:

\[ 1\sim -1, \qquad 1\sim1. \]

But:

\[ 1+1=2, \]
\[ (-1)+1=0, \]

and:

\[ 2 \not\sim 0. \]

Therefore the equivalence is not a congruence for addition.

\[ \boxed{ \text{safe Set identification} \not\Rightarrow \text{lawful algebraic quotient}. } \]
Example 22 — Separate Witnesses Are Not One Shared Witness
Main idea: quantifier scope

Let:

\[ P_1(w) \iff w=0, \]
\[ P_2(w) \iff w=1. \]

Then:

\[ \exists w_1P_1(w_1) \]

and:

\[ \exists w_2P_2(w_2) \]

are both true.

But:

\[ \boxed{ \nexists w [ P_1(w) \land P_2(w) ]. } \]

The Passport must preserve whether independent or shared witnesses are required.

Example 23 — Coupled Witnesses
Main idea: explicit coupling relation

Let:

\[ w_1,w_2 \in \mathbb Z. \]

Suppose first Branch requires:

\[ w_1 = x+1, \]

second requires:

\[ w_2 = 2x, \]

and their coupling requires:

\[ K(w_1,w_2) \iff w_2=2(w_1-1). \]

The combined feasibility statement is:

\[ \boxed{ \exists w_1\exists w_2: R_1(x,w_1) \land K(w_1,w_2) \land R_2(x,w_2). } \]

This is ordinary coupled-witness / CSP-style mathematics.

17. Full BM Combined Example

Example 24 — Regime-Dependent Feedback Configuration
Main idea: Branches + Law Space + Interaction + feedback + Dynamic Closure

Let continuous state:

\[ x\in\mathbb R. \]

Let material class:

\[ m\in\{A,B\}. \]

Let active regime:

\[ \lambda\in\{0,1\}. \]

Native law family

\[ y = k_{\lambda,m}x. \]

Feedback law

\[ x_{n+1} = 3-y_n. \]

Regime update

\[ \lambda_{n+1} = \mathbf 1_{x_n>1}. \]

Material persistence

\[ m_{n+1} = m_n. \]

Candidate BM decomposition

  • continuous-state Branch carrying \(x\);
  • material-state Branch carrying \(m\);
  • law/regime Branch carrying \(\lambda\);
  • constitutive Interaction producing \(y\);
  • feedback Operation updating \(x\);
  • regime Operation updating \(\lambda\).

Now propose reduced export:

\[ R(x,m,\lambda)=x. \]

Can \(x\) alone determine future \(x\)?

No, because:

\[ x_{n+1} = 3-k_{\lambda,m}x_n. \]

Equal \(x\)-values with different \((m,\lambda)\) can produce different next states.

Therefore:

\[ \boxed{ R(x,m,\lambda)=x \text{ fails Dynamic Closure}. } \]

Retain:

\[ R'(x,m,\lambda) = (x,m,\lambda). \]

Then, assuming the coefficient table \(k_{\lambda,m}\) is part of the declared law data, the next state is determined.

The additional Branch distinctions are retained because the mathematics requires them, not because BM prefers more Branches.

18. Heterogeneous Thermal-Control Configuration

Example 25 — Electrical + Thermal + Stochastic Sensor + Control
Main idea: heterogeneous Configuration · feedback · Passport · Root

Native electrical law

\[ P_e=VI. \]

Native thermal law

\[ C\dot T = \eta P_e - h(T-T_a). \]

Sensor model

\[ Y = T+\varepsilon, \qquad \varepsilon \sim \mathcal N(0,\sigma^2). \]

Controller

\[ e = T_\star-\widehat T, \]
\[ u = \operatorname{sat}_{[0,1]} (K_pe). \]

Actuator

\[ V = uV_{\max}. \]

One lawful Branch decomposition

A useful decomposition may distinguish:

  • a thermal-state Branch carrying \(T\);
  • an electrical Branch carrying the circuit state needed for \(VI\);
  • a stochastic observation Branch carrying the sensor law;
  • an estimation Branch carrying \(\widehat T\) if estimator state is independently required;
  • a controller Branch carrying control state/rules;
  • a safety Branch carrying safety obligations.
Quantities such as \(P_e\), \(e\), and \(u\) may remain Leaves unless the declared problem requires them to become separate Branches.

Useful Leaves

\[ L_P=P_e, \qquad L_{\dot T}=\dot T, \qquad L_e=e, \qquad L_u=u. \]

Passport obligations

  • temperature units;
  • current and voltage bounds;
  • actuator saturation;
  • sensor uncertainty semantics;
  • sample time;
  • distinction between \(T\) and \(\widehat T\);
  • active thermal model/regime;
  • safety requirement \(T\le T_{\max}\).

Semantic dependency loop

\[ T \rightsquigarrow Y \to \widehat T \to e \to u \to V \to P_e \to \dot T \to T. \]

The first arrow is stochastic. Several middle arrows are deterministic. The thermal update is dynamical.

Coherence diagnostic

Suppose both sensor and model estimator provide temperature estimates:

\[ \widehat T_{\mathrm{sensor}}, \qquad \widehat T_{\mathrm{model}}. \]

Declare:

\[ \boxed{ | \widehat T_{\mathrm{sensor}} - \widehat T_{\mathrm{model}} | \le \delta. } \]

A violation is a coherence defect. It is not silently averaged away.

Realization

The Configuration is globally realizable only if the coupled system admits a trajectory satisfying the full domain, stochastic, control, feedback, and safety obligations.

\[ \boxed{ \mathfrak F(C;c) \neq \varnothing. } \]

If one lawful trajectory \(\xi\) is selected:

\[ \boxed{ T_{\mathrm{BM}} = (C,\xi,\Pi,\omega,\Lambda) } \]

is the realized Tree.

Response and Root

Suppose the controller Response is:

\[ Y_R=u^\star. \]

Export:

\[ E_{\mathrm{act}}(Y_R)=u^\star. \]

If actuator Passport requires:

\[ 0 \le u^\star \le 1 \]

and all other actuator conditions hold, then:

\[ \boxed{ u^\star \text{ is a Root for the actuator receiver}. } \]

It then re-enters:

\[ u^\star \to V \to P_e \to \dot T. \]

19. Research-Scale Native Mathematics

Example 26 — Navier–Stokes Energy Leaves
Main idea: classical PDE mathematics carried through BM roles

Consider periodic incompressible Navier–Stokes:

\[ \partial_tu + (u\cdot\nabla)u = -\nabla p + \nu\Delta u + f, \]
\[ \nabla\cdot u=0. \]

Define energy:

\[ L_E = \frac12 \int_\Omega |u|^2\,dx. \]

Dissipation Leaf:

\[ L_D = \nu \int_\Omega |\nabla u|^2\,dx. \]

Forcing Leaf:

\[ L_F = \int_\Omega f\cdot u\,dx. \]

Under sufficient smoothness, periodicity, and incompressibility:

\[ \boxed{ \frac{dL_E}{dt} = -L_D + L_F. } \]

These are classical PDE identities.

BM can track which derived quantities later Tasks require without pretending to have discovered the energy identity.

This example does not solve the three-dimensional Navier–Stokes regularity problem.
Example 27 — Spectral Passport Preserves Energy but Loses Phase
Main idea: Task-relative information loss

Let Fourier coefficients be:

\[ \widehat u(k). \]

Consider magnitude-only representation:

\[ r(\widehat u) = \{ |\widehat u(k)| \}_k. \]

Modal energy:

\[ |\widehat u(k)|^2 \]

remains recoverable.

Therefore a spectral energy Task:

\[ E_{\mathrm{spec}} = \sum_k |\widehat u(k)|^2 \]

survives the reduction.

But nonlinear Fourier interactions contain phase-sensitive products such as:

\[ \widehat u(p) \widehat u(q), \qquad p+q=k. \]

Two fields can have identical modal magnitudes and different phases, producing different nonlinear transfer.

\[ \boxed{ \begin{array}{c} \text{energy Task: may survive magnitude-only representation},\\ \text{phase-sensitive transfer Task: generally does not}. \end{array} } \]
Example 28 — Quantum Channel Task Dependence
Main idea: operator-sector Passport semantics

Let:

\[ \rho = |+\rangle\langle+| = \frac12 \begin{pmatrix} 1&1\\ 1&1 \end{pmatrix}. \]

Apply complete dephasing in the computational basis:

\[ \mathcal D(\rho) = \frac12 \begin{pmatrix} 1&0\\ 0&1 \end{pmatrix}. \]

\(\sigma_z\) Task

\[ \operatorname{Tr} (\rho\sigma_z) = 0, \]
\[ \operatorname{Tr} (\mathcal D(\rho)\sigma_z) = 0. \]

This Task survives.

\(\sigma_x\) Task

\[ \operatorname{Tr} (\rho\sigma_x) = 1, \]
\[ \operatorname{Tr} (\mathcal D(\rho)\sigma_x) = 0. \]

This Task does not survive.

\[ \boxed{ \text{channel preserves some Tasks while destroying distinctions required by others}. } \]
Operator theory and quantum probability remain the native mathematics. BM supplies the Task/Passport organization.

20. Candidate Structures

Example 29 — Candidate Seed Role
Status: Candidate structure, not core

Consider the genuine iteration:

\[ G(s) = \frac12s+1. \]

Start:

\[ S_0=0. \]

Define a candidate Seed role only because the model also declares an export condition:

\[ |G(S_n)-S_n| < 0.05. \]

Iterates:

\[ S_1=1, \]
\[ S_2=1.5, \]
\[ S_3=1.75, \]
\[ S_4=1.875, \]
\[ S_5=1.9375, \]
\[ S_6=1.96875. \]

At \(S_6\):

\[ |G(S_6)-S_6| = |1.984375-1.96875| = 0.015625 < 0.05. \]

So the declared export gate has been reached.

But that produces only an export candidate.

\[ \boxed{ \text{Seed export} \not\Rightarrow \text{Root}. } \]

A receiver must still accept the result.

The convergence and arithmetic here are ordinary fixed-point iteration. Seed is only the candidate BM role assigned to the generative phase.

21. Failure Laboratory

BM is most useful when it identifies exactly which mathematical obligation failed.

Failure Example Diagnosis
Type mismatch Feed a pressure value directly into a temperature-only law. Receiving type or Interface fails.
Domain failure Evaluate real \(\log x\) at \(x\le0\). Operation lies outside its true domain.
Passport applicability failure Submit a function where the receiver Passport applies only to matrices. Passport cannot yet be evaluated.
Passport rejection A valid matrix candidate violates the required rank condition. Passport applies but rejects.
Branch explosion Declare \(x,x^2,x^3,\sin x\) separate Branches without need. No separation witness.
Under-branching Discard a regime variable needed for future dynamics. Continuation obligation fails.
Static/dynamic confusion Representation preserves a present Task but not future evolution. Dynamic Closure fails.
Separate/joint confusion Each constraint has a witness but no common witness exists. Witness scope fails.
Local/global confusion All pairwise constraints are satisfiable but the global system is not. Global realization obstruction.
Silent law selection \(\Lambda(C)\) contains several laws but one is chosen without a selector. Selection is unjustified.
Invalid quotient An equivalence relation fails Operation congruence. Structure does not descend.
Wrong semantic sector A Markov kernel is treated as an ordinary deterministic function. Sector firewall violated.
Coherence failure Two legitimately comparable paths give different outputs. Path coherence fails.
Root overreach A value accepted by one receiver is assumed valid for all others. Root receiver-relativity violated.
Stale certificate An upstream repair changes data used by a previously certified Root. Dependency closure requires revalidation.
Candidate-term overreach A Seed or Rooting label is used as if it supplied a theorem. Candidate status does not provide mathematical conclusions.
