1. Purpose

This is the formal mathematical revision ledger.

\[ \boxed{ \text{previous form} \longrightarrow \text{mathematical reason} \longrightarrow \text{corrected form} \longrightarrow \text{dependency update} \longrightarrow \text{new status}. } \]

Informal drafting chronology, conversations, cosmetic edits, abandoned wording, and ordinary website maintenance do not belong here unless they changed the mathematical public record.

2. Revision Principles

\[ \boxed{ \text{correction} \neq \text{erasure}. } \]
\[ \boxed{ \text{mathematical validity} \neq \text{historical novelty} \neq \text{physical interpretation} \neq \text{empirical validation}. } \]
\[ \boxed{ \text{new terminology} \not\Rightarrow \text{new mathematics}. } \]
\[ \boxed{ \text{failed stronger claim} \longrightarrow \text{preserved counterexample} \longrightarrow \text{corrected scope}. } \]

Historical entries remain visible when they explain why the current formulation exists. A superseded equation remains part of the mathematical history but does not remain the governing equation.

3. Current Governing Rule

\[ \boxed{ \text{current canonical pages} > \text{superseded historical formulation}. } \]

When an older changelog entry conflicts with a later correction, the later explicitly superseding entry governs.

The changelog records history; it is not an excuse to keep obsolete definitions active.

6. BM Identity Strengthened

September 8, 2026
BM FOUNDATIONS

BM explicitly identified as a mathematical metaframework

The descriptive phrase meta-structural mathematics of lawful representation and transformation is retained, but no longer carries the full burden of the definition.

\[ \boxed{ \begin{array}{c} \text{Branch Mathematics is a mathematical metaframework for carrying}\\ \text{one mathematical problem through multiple distinct lawful}\\ \text{mathematical Branches while preserving their native mathematics.} \end{array} } \]

BM is explicitly plural: Branches, Operations, Interactions, Passports, Interfaces, Configurations, realization, coherence, refinement, information, defects, export, and re-entry coexist.

\[ \boxed{ \text{Branch} \to \text{Interaction} \to \text{Leaf} \to \text{Tree} \to \text{Root} } \]

remains a useful teaching spine but is no longer permitted to stand for the entirety of BM.

7. Role-Carrier Separation Added

September 8, 2026
BM ROLE SEMANTICS

BM roles separated from native mathematical species

\[ \boxed{ x \models_C \rho } \]

now means that mathematical object \(x\) occupies BM role \(\rho\) in Configuration \(C\).

\[ \boxed{ \text{BM role} \neq \text{new mathematical species}. } \]

The same carrier may occupy several roles:

\[ z \models_C \mathrm{Leaf} \land \mathrm{Response} \land \mathrm{Root}_{B_r}. \]

This correction became a principal pseudo-math firewall throughout the public corpus.

8. Problem Scope and Obligation Closure Formalized

September 8, 2026
BM SCOPE DEPENDENCY

Branch and representation claims made explicitly scope-relative

\[ \boxed{ \mathfrak S_P } \]

denotes the declared mathematical scope of problem \(P\).

Terminal obligations:

\[ \mathscr T_P. \]

Active obligations:

\[ \boxed{ \mathscr Q_P = \operatorname{ReqCl}_{\mathfrak D_C} (\mathscr T_P). } \]

This prevents a representation from being declared sufficient only after the problem scope has been weakened to excuse its information loss.

\[ \boxed{ \text{representation choice} \not\Rightarrow \text{permission to redefine the problem scope}. } \]

9. Branch Admissibility and No-Explosion Rule

September 8, 2026
BM BRANCH

A mathematical object is no longer automatically a Branch

\[ \boxed{ \text{mathematical object} \not\Rightarrow \text{BM Branch}. } \]

Separate Branch status must survive a scope-relative coarsening audit.

Where a common representation carrier exists:

\[ R_{\mathcal B}: X_P \to Y_{\mathcal B}. \]

A proposed collapse:

\[ q: Y_{\mathcal B} \to Y' \]

is invalid when a required obligation no longer descends.

\[ \boxed{ T \neq \widetilde T \circ q \circ R_{\mathcal B}. } \]

The public no-explosion rule is now explicit:

\[ \boxed{ x,\; x^2,\; x^3,\; \sin x \text{ are not four Branches merely because four expressions were named.} } \]

Branch count is not treated as fundamental mathematical data.

10. Operation / Interaction Architecture Corrected

September 8, 2026
BM OPERATION INTERACTION

Interaction no longer treated as a separate transformation species

Operation is the general typed lawful transformation/relation role.

\[ O: D_O \subseteq X \to Y. \]

Interaction is an Operation or native relation with declared joint-participation structure.

\[ \boxed{ \partial I = ( B_{i_1}^{r_1}, \ldots, B_{i_k}^{r_k} ), \qquad k\ge2. } \]

Unary processing remains an Operation unless multiple declared roles are jointly participating.

Interaction Non-Inheritance retained as governing firewall

\[ \boxed{ \text{input structure} \not\Rightarrow \text{output structure}. } \]

11. Leaf Status Tightened

September 8, 2026
BM LEAF

A Leaf remains an identified derived result retained for later use.

\[ z = I(\ldots), \qquad \boxed{ L_j = \ell_j(z). } \]

Not every intermediate equation or named quantity is automatically promoted to Leaf status.

Likewise, a Leaf does not become a separate Branch merely because it is reused later.

12. Contract and Passport Separated

September 8, 2026
BM CONTRACT PASSPORT

Reusable obligation schema separated from operative instance

\[ \boxed{ \mathcal C^\rho = (\Sigma^\rho,\Phi^\rho) } \]
\[ \boxed{ \mathcal P^\rho_{\theta,c} = \operatorname{Inst}_{\theta,c} (\mathcal C^\rho). } \]

Contract is a reusable schema. Passport is the instantiated typed obligation family actually operating in a Configuration.

A Contract object remains optional when no reusable schema is needed.

13. Passport Applicability Distinguished from Rejection

September 8, 2026
BM PASSPORT DOMAIN
\[ \boxed{ \operatorname{Acc}(\mathcal P) \subseteq D_{\mathcal P}. } \]

The three cases are now kept distinct:

  • \(x\notin D_{\mathcal P}\): Passport is not applicable;
  • \(x\in D_{\mathcal P}\setminus\operatorname{Acc}(\mathcal P)\): Passport applies and rejects;
  • \(x\in\operatorname{Acc}(\mathcal P)\): Passport applies and accepts.
\[ \boxed{ \text{not applicable} \neq \text{applicable but false}. } \]

14. Configuration Ladder Formalized

September 8, 2026
BM CONFIGURATION REALIZATION
\[ \boxed{ \text{candidate} \to \text{well formed} \to \text{locally admissible} \to \text{globally realizable} \to \text{realized Tree}. } \]

Well-formedness:

\[ \boxed{ \mathrm{WF}(C). } \]

Local admissibility:

\[ \boxed{ \mathfrak F(U_i;C,c) \neq \varnothing \qquad \forall U_i. } \]

Global realizability:

\[ \boxed{ \mathrm{GR}(C;c) \iff \mathfrak F(C;c) \neq \varnothing. } \]

Candidate mathematical structure is therefore no longer presented as an already-realized Tree.

15. Semantic Dependency Structure Added

September 8, 2026
BM NETWORK DEPENDENCY

The governing semantic dependency object is:

\[ \boxed{ \mathfrak D_C. } \]

It may be represented by a graph, DAG, hypergraph, factor graph, category, operator network, or other sector-correct structure.

Dependency closure:

\[ \boxed{ \operatorname{Cl}_{\mathfrak D_C}(S). } \]

replaces simplistic universal “downstream graph” language.

In cyclic systems the affected region may be a strongly connected component. Hyperedge/global constraints must be explicit rather than hidden outside the Network.

16. Realization Family Made Explicit

September 8, 2026
BM REALIZATION
\[ \boxed{ \mathfrak F(C;c) = \text{family of lawful realizations of Configuration }C. } \]

Realization includes all declared:

  • Branch admissibility;
  • Operation domains;
  • Interfaces;
  • Passports;
  • law/regime data;
  • witness/coupling obligations;
  • coherence;
  • feedback;
  • global constraints.

Existence and selection are now formally separated.

\[ \boxed{ \mathfrak F(C;c) \neq \varnothing \not\Rightarrow \text{canonical }\xi. } \]

17. Tree Definition Corrected

September 8, 2026
BM TREE

Tree changed from organized computation to realized Configuration

\[ \boxed{ T = (C,\xi,\Pi,\omega,\Lambda), \qquad \xi \in \mathfrak F(C;c). } \]

where:

  • \(C\) is the Configuration;
  • \(\xi\) is a selected lawful realization;
  • \(\Pi\) is required provenance;
  • \(\omega\) is required dependency/order context;
  • \(\Lambda\) is law/regime context.
\[ \boxed{ \text{Configuration} \neq \text{Tree}. } \]

Tree remains BM terminology and need not be a graph-theoretic tree.

18. Response, Export, Root, and Re-entry Rebuilt

September 8, 2026
BM RESPONSE ROOT
\[ \boxed{ \text{Tree} \to \text{Response} \to \text{Export} \to \text{receiver gate} \to \text{Root} \to \text{re-entry}. } \]

Export:

\[ E_r: D_{E_r} \subseteq \mathcal Y_T \to \mathcal R_r. \]

Root gate:

\[ \boxed{ r \text{ is Root for }B_r \iff r \in \operatorname{Acc} (\mathcal P_R^{B_r}). } \]

Root is explicitly receiver-relative.

\[ \boxed{ \text{Root}_{B_1}(r) \not\Rightarrow \text{Root}_{B_2}(r). } \]

19. Intrinsic “Root Dynamics” Demoted

September 8, 2026
BM ROOT CLASSICAL DYNAMICS

Ordinary dynamics no longer presented as universal Root mathematics

Fixed points, cycles, affine recurrences, stability, event rates, thresholds, derivatives, and convergence remain available when a native model defines them.

\[ R_{n+1} = F(R_n) \]

is ordinary iteration when a genuine self-map exists.

\[ \boxed{ \text{Root reuse} \not\Rightarrow \text{iteration}. } \]
\[ \boxed{ \text{iteration} \not\Rightarrow \text{convergence}. } \]

Earlier changelog entries concerning affine Root convergence and local fixed-point stability remain historically correct as statements about those specific dynamical systems, but they are no longer classified as intrinsic laws of Roothood.

20. Rooting, Rebranching, and Seed Kept Candidate

September 8, 2026
BM CANDIDATE

Candidate structures separated from core Root semantics

Rooting:

\[ \boxed{ \mathcal A: D_{\mathcal A} \subseteq A_{\mathrm{attach}} \times A_R(B') \to X'. } \]

remains candidate.

Rebranching remains candidate and is not implied by Rooting.

\[ \boxed{ \text{Rooting} \not\Rightarrow \text{Rebranching}. } \]

Seed remains candidate and requires an actual generative process plus export condition:

\[ S_0 \xrightarrow{G} S_1 \xrightarrow{G} \cdots \xrightarrow{\text{export}} Y. \]
\[ \boxed{ \text{initial data} \not\Rightarrow \text{Seed}. } \]

21. Law Space Restricted to an Active Specialized Lane

September 8, 2026
BM LAW SPACE

Law Space remains active mathematics but is not imposed as a universal separate Branch.

\[ \boxed{ \Lambda: \Omega_{\mathscr L} \rightrightarrows \mathscr L. } \]

If:

\[ |\Lambda(C)| > 1, \]

and downstream mathematics depends on the selected law, BM may not choose silently.

\[ \boxed{ \exists \lambda \not\Rightarrow \text{canonical }\lambda. } \]

22. Dynamic Closure Corrected to the Realized Image

September 8, 2026
BM GURF DYNAMIC CLOSURE
\[ \Phi: A \to A, \qquad R: A \to Y, \qquad Y_R = R(A). \]

Exact Dynamic Closure now requires:

\[ \boxed{ \widetilde\Phi: Y_R \to Y_R, \qquad R\circ\Phi = \widetilde\Phi \circ R. } \]

No reduced evolution is required on points outside the realized image \(Y_R\).

\[ \boxed{ R(x)=R(x') \Longrightarrow R(\Phi(x)) = R(\Phi(x')). } \]

23. Coherence Tightened

September 8, 2026
BM COHERENCE

Coherence now explicitly requires:

  1. common lawful input domain;
  2. a mathematically legitimate comparison space;
  3. agreement under the declared comparison.
\[ x \in D_{P_1} \cap D_{P_2}, \]
\[ q_1: Y_1 \to Q, \qquad q_2: Y_2 \to Q, \]
\[ \boxed{ q_1P_1(x) = q_2P_2(x). } \]

Comparison maps may not be invented solely to force equality.

\[ \boxed{ \text{pairwise coherence} \not\Rightarrow \text{global coherence}. } \]

24. Repair Made Dependency-Aware

September 8, 2026
BM REPAIR CERTIFICATION

General admissible repair:

\[ \boxed{ \mathscr R_{\mathrm{adm}} \subseteq \mathsf{Conf} \times \mathsf{Conf}. } \]

A repair changing region \(S\) triggers revalidation of:

\[ \boxed{ \operatorname{Cl}_{\mathfrak D_C}(S). } \]

unless an invariance theorem proves the affected certificate remains valid.

\[ \boxed{ \text{repair} \not\Rightarrow \text{old downstream certificates remain valid}. } \]

25. Refinement and Lattice Claims Tightened

September 8, 2026
BM REFINEMENT

In the deterministic common-source special case:

\[ R_1: X_P \to Y_1, \qquad R_2: X_P \to Y_2, \]
\[ \boxed{ R_1 = A_{21} \circ R_2. } \]

may support:

\[ \mathcal B_1 \preceq_{P,\mathcal T} \mathcal B_2. \]

The relation is a preorder under fixed comparison semantics. Poset language requires quotienting mutual refinement. Lattice language requires actual existence of meets and joins.

\[ \boxed{ \text{preorder} \not\Rightarrow \text{lattice}. } \]

26. Markov Test-Function Notation Corrected

September 8, 2026
STOCHASTIC NOTATION

Generic expectation pullback no longer written as \(K^\dagger\)

For Markov kernel:

\[ K: X \rightsquigarrow Y, \]

the generic test-function action is:

\[ \boxed{ (K\varphi)(x) = \int_Y \varphi(y) K(x,dy). } \]

Adjoint notation \(K^\dagger\) is reserved for contexts where an actual adjoint structure has been defined.

27. Computability Firewall Added

September 8, 2026
BM COMPUTABILITY
\[ \boxed{ \text{existence} \neq \text{decidability} \neq \text{computability / constructibility} \neq \text{complexity}. } \]

A realization theorem does not automatically provide an algorithm. An algorithm does not automatically provide efficient computation.

BM PRIOR ART NO DUPLICATE THEORY

Specialized BM constructions must be reduced to established mathematics where possible

when established theory \(M\) completely realizes proposed subconstruction \(S\).

30. SOE Ownership Narrowed

September 8, 2026
GURF SOE OWNERSHIP

SOE retained as stable canonical response-operation specialization

\[ \boxed{ \mathrm{SOE} = \text{response specialization for mathematically significant Operation structure}. } \]

SOE no longer claims general ownership of:

  • function composition;
  • partial maps;
  • control theory;
  • fixed-point theory;
  • stability theory;
  • Markov kernels;
  • relations;
  • quantum channels;
  • generic numerical error analysis.

Those remain native or BM mathematics. SOE activates when Operation identity, order, handoff, provenance, history, feedback, or semantic sector changes the response problem.

REBIND removed as unnecessary standalone primitive

Interface replacement/revalidation already expresses the required mathematics.

\[ \boxed{ \mathcal I_n \longrightarrow \mathcal I_{n+1}. } \]

40. What Belongs in This Changelog

  • definition changes;
  • type/domain corrections;
  • theorem, proof, or counterexample changes;
  • equation generalizations or restrictions;
  • semantic-sector corrections;
  • ownership migrations;
  • candidate promotions or demotions;
  • freezes, closures, quarantines, and supersessions;
  • research-status changes;
  • realization-status changes;
  • major prior-art findings;
  • important numerical or experimental verdicts;
  • cross-page mathematical synchronization.

41. What Does Not Belong

  • ordinary spelling corrections;
  • color or layout changes;
  • informal brainstorming;
  • conversation history;
  • unpublished speculation with no mathematical consequence;
  • temporary naming ideas;
  • code refactoring that leaves the mathematics unchanged;
  • unverified bibliographic claims;
  • claims of novelty based only on project chronology.
