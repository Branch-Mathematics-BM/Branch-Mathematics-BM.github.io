Input syntax
  • One equation per line, or separate equations with semicolons.
  • ^ is accepted for powers.
  • 2x and 2(x+1) are accepted.
  • Multi-letter variables such as voltage, resistance, and mass_flow remain single variables.
  • Use parentheses for named functions: sin(x), cos(x), exp(x), log(x), sqrt(x), Abs(x).
  • A line without = is treated as an expression to simplify.
  • Use # for comments.
  • Generic undefined functions such as f(x) are not supported in this first solver.
  • Reserved mathematical constants include pi, E, I, and oo.

This is currently a symbolic algebra/system solver rather than a natural-language WolframAlpha replacement. SymPy performs the native symbolic mathematics; BM supplies the structural interpretation.

What the Calculator Is Actually Doing

Input → Parse → Branch factorization → Native solve → Leaves → Realization family → Tree status → Response

Task-relative Branch decomposition

The calculator constructs the equation-variable incidence structure. Statements linked by shared variables belong to the same connected computational component.

Distinct connected components can be separated for the current explicit solve Task because no submitted constraint couples their variables.

\[ \boxed{ \mathfrak F(C;c) = \prod_{k=1}^{m} \mathfrak F(B_k) } \]

for the explicit algebraic system when the submitted constraints contain no hidden cross-component conditions.

This is a task-relative computational Branch decomposition. It is not presented as the unique or globally canonical BM Branch decomposition of every possible later Task.

Operation / Interaction firewall

A multi-variable equation is a joint constraint relation. It is not called a separate BM Interaction merely because more than one variable appears.

Under automatic connected-component reduction, any shared-variable coupling already places the relevant statements in the same computational Branch.

\[ \boxed{ \text{multi-variable equation} \not\Rightarrow \text{cross-Branch Interaction}. } \]

A later calculator version can support explicitly declared heterogeneous Branches and then expose genuine cross-Branch Interactions without merging their native mathematical identities.

Leaves

Leaves shown by this calculator are actual derived mathematical objects, including:

  • normalized equations;
  • augmented matrices;
  • reduced row-echelon forms;
  • polynomial factorizations;
  • solution relations;
  • verification results.

Tree firewall

\[ \boxed{ T = (C,\xi,\Pi,\omega,\Lambda), \qquad \xi\in\mathfrak F(C;c). } \]

If the realization is unique, the calculator can identify that realization without making a selection.

If several realizations exist, it reports the family and refuses to invent a canonical one.

\[ \boxed{ \mathfrak F(C;c)\neq\varnothing \not\Rightarrow \text{canonical }\xi. } \]

Root firewall

A solution is a Response. It becomes a Root only relative to a specified receiving Passport.

\[ \boxed{ r \text{ Root for }B_r \iff r\in \operatorname{Acc} (\mathcal P_R^{B_r}). } \]
