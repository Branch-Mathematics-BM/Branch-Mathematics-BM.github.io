Interfaces

Interfaces and Information Loss

An interface decides which distinctions leave one subsystem and become available to another. Branch Mathematics asks whether the interface preserves exactly the distinctions required by the downstream contract—and what breaks when it does not.

Short version: an interface can discard enormous amounts of native detail lawfully, but only when every distinction it removes is irrelevant to every allowed downstream task, context, and continuation.

Why interfaces matter

Most large systems are not solved as one indivisible mathematical object. They are decomposed into components, subsystems, domains, modules, regions, or stages.

Those pieces communicate through interfaces.

Every interface is a decision about which distinctions cross a boundary and which remain hidden behind it.

If the interface carries too much, the system may be unnecessarily expensive. If it carries too little, downstream computation may become impossible, ambiguous, or incorrect.

The simplest interface question

Suppose subsystem A has native state x, and subsystem B receives only an interface state:

R(x) = q

If two internal states x and x′ produce the same interface value, then B cannot distinguish them using that interface alone.

That is safe only when every downstream response required by the contract also treats them identically.

R(x)=R(x′) ⇒ B(x,c)=B(x′,c)

for every allowed external context c.

Contextual equivalence

The important phrase is for every allowed context.

Two local states might be indistinguishable when connected to one neighboring subsystem and distinguishable when connected to another.

x ∼ x′ ⇔ B(x,c)=B(x′,c) for all allowed contexts c

This gives a portable exact interface equivalence.

A portable interface must survive every context the Passport allows, not merely the context used during one deployment.

Deployment-specific versus portable interfaces

Deployment-specific interface

Built for one known peer context. It can merge states that happen to behave identically in that deployment.

Portable interface

Must remain correct across every allowed peer context, so it may need to preserve more distinctions.

The extra width required for portability is not waste. It is the mathematical price of surviving a larger context family.

A tiny example

One subsystem, two possible receivers

Suppose subsystem A has three internal states:

X = {a,b,c}

Receiver 1 only asks whether the state is c. Then a and b may safely share one interface symbol.

q₀ = {a,b},   q₁ = {c}

Receiver 2 later asks whether the state is b. That same interface is no longer sufficient.

The native subsystem did not change. The receiver contract changed.

Information loss is receiver-relative

When an interface merges two states, the distinction between them is unavailable downstream unless another source later supplies it.

BM does not call every such merge “bad information loss.” Some distinctions are irrelevant to the receiver and can be removed lawfully.

lawful compression = discard only distinctions outside the declared obligation

This is why information loss must be discussed relative to a declared task and admissible context rather than as an unqualified physical slogan.

BM does not turn interface compression into a universal physical conservation law. The claim is about distinguishability under declared maps, sources, and receiver obligations.

Coupling can require more than the final task

A subsystem may need to export distinctions that the final observer never sees directly because those distinctions affect the dynamics of the neighboring subsystem.

This creates a crucial rule:

coupling obligations must be preserved before task-only compression

For a boundary trace g, suppose coupling depends on Λg and a final task depends on Lg. Then an exact port must preserve both.

Eport = ker(Λ) ∩ ker(L)

A task-only quotient based on L can be too coarse if the discarded boundary distinction still changes the neighboring dynamics through Λ.

PDE ports

Partial differential equations make this especially concrete.

A domain may contain an infinite-dimensional field, yet communicate with a neighboring domain only through a boundary trace, flux, or operator response.

Interior PDE state
Boundary trace
Port operator
Neighbor coupling
Task response

BM asks which boundary distinctions are necessary for the actual deployment.

If the relevant transfer from admissible interior histories to receiver-visible boundary behavior is compact, positive-tolerance port width can be finite even when the full trace space is infinite-dimensional.

Task-filtered transfer operators

A port should not be judged solely by the complexity of the full transfer operator if the receiver only observes a filtered response.

If:

T : W → U

maps admissible histories into a port space, and:

C : U → Y

is the receiver task, then the relevant task operator is:

CT

rather than necessarily T itself.

The minimal receiver-facing interface depends on the task-filtered transfer, not automatically the full native port.

Minimal composable interfaces

Suppose subsystem i can be placed in many allowed external contexts. Define its external response profile by:

Pi(xi)(x-i) = B(xi,x-i)

Two local states are contextually equivalent when their response profiles agree for every allowed external state.

xi ∼i x′i ⇔ Pi(xi) = Pi(x′i)

The quotient by this relation is the coarsest exact portable product-composable interface for that declared response family.

Local correctness does not guarantee global composition

Each subsystem can be individually repaired or reduced correctly and the full coupled system can still fail.

Global composition additionally requires compatible interface values.

RI ∩ [π₁(E₁) × ··· × πₘ(Eₘ)] ≠ ∅

Conceptually: the locally valid subsystem states must be able to meet on one globally realizable interface configuration.

BM firewall: locally valid interfaces do not automatically compose into a globally realizable system.

Distributed cuts create realization surcharge

A centralized receiver may need only a small amount of semantic information, while a distributed architecture must transmit more because no single route initially has access to the combined state.

Parity across many sources

The final parity task is one bit:

x₁ ⊕ x₂ ⊕ ··· ⊕ xₙ

But if each source crosses a separate cut before aggregation, each route may need to transmit a bit.

centralized semantic width = 1 bit
direct distributed cut cost = n bits

The difference is a locality surcharge created by the architecture, not by the final task itself.

Routes can be redundant without being useless

Two routes may carry the same semantic distinction. The second route adds no new task dimension but can still improve failure resilience.

In a linear setting, route j adds no new semantic dimension beyond route set S when:

Hj = KjHS

equivalently:

ker(HS) ⊆ ker(Hj)

The route can be semantically redundant and still be valuable for robustness.

Causal interfaces

An interface can also change through time.

A distinction may need to cross a cut now because the environment will no longer be able to reveal it later. Another distinction may safely be dropped now because a future observation will reacquire it before it is needed.

current cut obligation depends on future reveal opportunities

BM therefore treats interface design as a spacetime problem when deadlines and future observations matter.

Reacquisition changes retention cost

Suppose a distinction matters during two separated time intervals. During the gap, the system has two choices:

Keep it

Continue storing or transmitting the distinction through the gap.

Reacquire it

Discard it temporarily and obtain it again from an external distinguishing observation before the next deadline.

This is a real architectural tradeoff. Deterministic computation alone cannot recreate a distinction that the interface discarded.

Approximate interfaces

At positive tolerance, an interface need not preserve every receiver-visible profile exactly.

The interface can group local states into cells as long as each cell admits a receiver profile within tolerance.

CRad(A) = inff sups∈A,c∈C d(B(s,c),f(c))

The approximate portable interface problem becomes a covering problem in the space of contextual response profiles.

w(ε) = log₂ N(ε)

where N(ε) is the minimum number of contextual profile representatives needed at tolerance ε.

Robustness matters at interfaces

Two interfaces can have the same width and tolerance while having different remaining reserve.

If the worst cell radius is r, the remaining tolerance reserve is:

reserve = ε - r

A slightly finer interface can be more robust to perturbation even when a coarser interface is still nominally admissible.

Minimal width does not guarantee easy construction

The exact or approximate interface may be small while discovering it is difficult.

The system may have an implicit contextual response, a large state space, complicated coupling, or hard combinatorial constraints.

interface width ≠ interface construction complexity

Minimal width also does not guarantee physical realizability

A mathematically minimal interface may fail the required implementation category.

Examples include:

1
Geometric obstruction The quotient may not embed into the required Euclidean dimension.
2
Locality obstruction A centralized interface may not decompose into the allowed local architecture.
3
Quantum obstruction A desired carrier may violate CPTP realizability or no-broadcasting constraints.
4
Conditioning obstruction A reduced port may exist but amplify approximation error unacceptably.

The interface design procedure

A lawful BM interface is built in this order:

1
Identify the native boundary State what variables, traces, histories, or operators are actually available at the cut.
2
Declare the downstream Passport Specify allowed contexts, tasks, horizons, tolerances, and implementation constraints.
3
Include coupling obligations Preserve distinctions needed by neighboring dynamics before task-only compression.
4
Construct contextual equivalence or cover Merge only states whose downstream profiles are exactly equal or within the declared tolerance.
5
Check composition Verify that locally valid interface states admit a globally realizable coupled configuration.
6
Check implementation Test locality, smoothness, causal timing, physical admissibility, and robustness.

The key idea

An interface is not a miniature copy of the subsystem. It is the distinction structure the rest of the system still needs.

That distinction is what lets BM connect model reduction, PDE ports, distributed cuts, causal memory, and quantum carriers under one receiver-relative interface question while preserving the native mathematics of each sector.
