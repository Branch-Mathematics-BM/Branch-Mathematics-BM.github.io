Exact vs Approximate Representations

Exact representation asks whether required responses are preserved with no error. Approximate representation asks how much structure can be compressed while keeping every declared error within tolerance.

Short version: approximation is not merely “exact mathematics with a little error added.” Positive tolerance can change the geometry, combinatorics, optimal representation, robustness, and even whether a finite interface exists.

The exact question

Suppose a representation R maps native states into a reduced state space. If two native states are mapped to the same reduced state, exact task sufficiency requires that the declared task give exactly the same response on both.

R(x)=R(x′) ⇒ T(x)=T(x′)

Equivalently:

ker(R) ⊆ ker(T)

Exact mathematics therefore creates genuine equivalence classes: states can be merged only when the contract cannot distinguish them.

The approximate question

Now suppose the receiver tolerates an error of at most ε. Two states no longer need identical responses. They only need to be represented in a way that lets one decoder serve them both within the declared tolerance.

That turns the problem from exact equivalence into geometry.

Exact representation asks which states are identical to the receiver. Approximate representation asks which groups of states can share one representative without exceeding tolerance.

Exact classes versus approximate cells

Exact sector

Classes come from an equivalence relation. Equality is transitive, so the exact quotient has canonical partition structure once the contract is fixed.

Approximate sector

“Close enough” need not be transitive. A can be close to B and B close to C while A and C cannot safely share one decoder cell.

That single difference is why approximate mathematics cannot generally be handled by simply replacing equality with a tolerance symbol.

A three-point example

Pairwise closeness can fail as a shared cell

Place three task outputs at the vertices of an equilateral triangle in the Euclidean plane, with side length 2ε.

Every pair can fit inside a radius-ε ball whose center is the midpoint of that pair.

But all three points together require a larger circumradius:

radius = 2ε / √3 > ε

So pairwise admissibility does not imply that the entire set can share one approximate decoder value.

Approximate BM firewall: pairwise threshold compatibility is not generally sufficient for a whole cell. In general metric outputs, the natural obstruction can be hypergraphic rather than merely graph-theoretic.

Cell radius is the right object

For a set of states that share one representation label, the decoder must choose a single output representative that works for all of them.

The relevant quantity is therefore a radius:

rad(A) = infz supy∈A d(y,z)

An approximate cell is admissible at tolerance ε when:

rad(A) ≤ ε

Pairwise diameter still gives useful bounds:

½ diam(A) ≤ rad(A) ≤ diam(A)

But radius and diameter are not generally identical.

Covering numbers replace exact class counts

In the exact finite case, the number of receiver-distinct classes is simply:

N(0) = |X / E|

At positive tolerance, the analogous quantity is a covering number:

N(ε) = minimum number of radius-ε decoder profiles needed to cover the declared response set

Branch Mathematics uses:

w(ε) = log₂ N(ε)

as an approximate semantic-width measure.

Why tolerance can make an infinite system finite-width

Exact representation may require infinitely many distinct states. Positive tolerance can change that dramatically when the receiver-visible behavior set is compact or precompact.

In a complete profile metric space:

N(ε) < ∞ for every ε > 0 ⇔ the receiver-visible profile set is relatively compact

This is especially important for PDEs and other infinite-dimensional systems.

Infinite exact state complexity does not force infinite positive-tolerance semantic width.

Heat equation example

Positive-time heat evolution suppresses high-frequency modes. Under suitable bounded-state and receiver norms, the evolved profile family can become compact.

At time zero, the full unit ball of an infinite-dimensional Hilbert space is not compact and can require infinitely many small tolerance balls.

After positive-time smoothing, the same receiver-visible family can admit finite covers at every positive tolerance.

exact/native dimension remains infinite
approximate receiver width can become finite

This is a property of the dynamics, receiver, admissible state set, and tolerance together.

Exact and approximate dynamic closure

The same separation appears in dynamics.

Exact closure requires every reduced successor fibre to be a singleton.

SR(q) = {R(Φx) : R(x)=q}
exact closure ⇔ |SR(q)| = 1 for every q

Approximate closure allows a fibre to have nonzero spread, but that spread creates unavoidable prediction error.

α(R) = supq diam SR(q)

The best one-step predictor radius satisfies:

α(R)/2 ≤ δ*1 ≤ α(R)

Exact closure is recovered when that ambiguity collapses to zero.

Approximate error accumulates through dynamics

A small local approximation error need not remain small after repeated evolution.

If a reduced update has amplification factor Lt and local defect δt, a typical error recurrence is:

et+1 ≤ Lt et + δt

This distinction matters:

Case Possible behavior
L < 1 Errors can contract.
L = 1 Errors can accumulate without amplification.
L > 1 Small local defects can grow rapidly.
BM firewall: small local approximation error does not imply small global error without conditioning or stability control.

Backward error budgets

If a final task has a tolerance, one can propagate the remaining budget backward through the dynamics.

Bt = (Bt+1 - δt) / Lt

If the numerator becomes negative, the architecture is infeasible under that error budget.

BM does not hide this by clamping the result to zero. Negative remaining budget is evidence that the current architecture cannot meet the declared tolerance.

Approximation introduces robustness questions

Two approximate representations can meet the same tolerance while having very different reserves.

Suppose a cell currently has radius r under tolerance ε. Its remaining task reserve is:

reserve = ε - r

A representation sitting just below the tolerance boundary can be less robust than a slightly finer representation with more margin.

Minimum width and maximum robustness need not be achieved by the same representation.

Exact realizability and approximate realizability are separate

A representation can be mathematically valid as an abstract quotient while failing the required implementation category.

The same issue remains in the approximate sector.

Examples include:

1
Smooth realization An abstract quotient may fail to admit a smooth Euclidean realization of the desired dimension.
2
Local implementation A centralized approximation may not decompose into the required local interfaces without extra width.
3
Quantum implementation An algebraic recovery relation may fail to correspond to an admissible CPTP recovery channel.
abstract approximation ≠ automatic admissible realization

Approximate optimal solutions need not form one canonical chain

Exact quotients often enjoy canonical order structure: one exact representation may refine another, and a greatest exact recoverable algebra can exist in appropriate sectors.

Positive tolerance can destroy that simplicity. Two different approximate representations can each be best for different directions or tasks, with neither containing the other.

That creates Pareto structure rather than one universal optimum.

approximate optimum can be partially ordered rather than uniquely greatest

Exact recovery versus approximate recovery in quantum systems

The quantum sector makes this distinction particularly clear.

Exact recovery of a task algebra asks whether the declared observables can be restored perfectly by an admissible quantum recovery channel.

Approximate recovery instead minimizes a physical recovery defect:

δA(N) = infR CPTP sup||X||≤1, X∈A ||X - E†N†R†(X)||

Exact recovery is the zero-defect case. Positive tolerance creates a family of approximately recoverable task algebras rather than necessarily one unique maximal algebra.

Approximate does not mean informal

Approximation is still a precise mathematical contract. A valid approximate claim must state:

A
The metric or norm Error has no numerical meaning until the geometry of comparison is declared.
B
The tolerance The receiver must state how much deviation is admissible.
C
The task and context Approximation is measured on declared responses, not unspecified behavior.
D
The horizon A one-step error guarantee is not automatically a long-horizon guarantee.
E
The realization class Abstract existence must be separated from smooth, local, stochastic, quantum, or other implementation requirements.

Exact versus approximate at a glance

Question Exact Approximate
State grouping Equivalence classes Admissible cells / covers
Task condition Equal response Response within tolerance
Complexity Number of quotient classes Covering / coloring / hypergraph complexity
Dynamics Single-valued reduced successor Bounded successor ambiguity and propagated error
Robustness Distance to exact failure Remaining tolerance reserve
Optimal structure Can be canonical in some sectors Often Pareto-valued or nonunique

The BM viewpoint

Branch Mathematics keeps exact and approximate sectors connected but distinct.

Exact mathematics determines which distinctions can be merged with no loss under the declared contract. Approximate mathematics determines how aggressively those distinctions can be grouped while keeping every declared error, horizon, realization, and robustness requirement within bounds.

Exactness asks whether a distinction may disappear. Approximation asks how far it may be blurred before the contract fails.

That distinction leads naturally into model reduction, semantic width, PDE compression, robustness, and approximate quantum recovery.
