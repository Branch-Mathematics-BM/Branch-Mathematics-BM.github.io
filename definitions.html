Definitions

Canonical mathematical reference for Branch Mathematics and GURF. Definitions specify roles, data, domains, semantics, abilities, limits, failure modes, and maturity status. A definition does not substitute for proof, realization, computation, or historical novelty.

1. How to Use This Reference

Branch Mathematics is a mathematical metaframework. Its role words organize native mathematical objects; they do not replace those objects.

\[ \boxed{ \text{role name} \neq \text{undeclared mathematical property} } \]

When reading any definition, ask five questions:

  1. What native mathematical object is involved?
  2. What BM or GURF role is being assigned?
  3. What is the true domain of the construction?
  4. What mathematical obligations must hold?
  5. What does the definition explicitly not imply?
Native-mathematics rule. Do the native mathematics correctly first. BM then records how distinct mathematical structures participate together and which distinctions, laws, interfaces, conditions, and provenance must remain available.

6. Branch Mathematics

Status: Core canonical framework definition

Branch Mathematics (BM) is a mathematical metaframework for carrying one mathematical problem through multiple distinct lawful mathematical Branches while preserving the native mathematics of each Branch and governing their lawful interaction, representation, transformation, realization, comparison, export, re-entry, refinement, and repair.

\[ \boxed{ \text{one problem} \longrightarrow \text{multiple lawful mathematical Branches} \longrightarrow \text{lawful combined mathematics} \longrightarrow \text{mathematical consequences} } \]

The phrase meta-structural mathematics of lawful representation and transformation describes BM's level of action; it does not replace the primary definition above.

Limits
  • BM does not replace native mathematics.
  • BM does not require every problem to use every BM structure.
  • BM does not make a false theorem true.
  • BM does not imply historical novelty merely from internal validity.

7. GURF

Status: Canonical response-specialized framework under BM governance

GURF is the response-specialized framework used when a mathematical problem contains essential response semantics: Tasks, observations, interventions, ambiguity, sufficiency, continuation, recovery, response constraints, or response-oriented distinguishability.

\[ \boxed{ \text{Which distinctions in the underlying state are necessary for the required response or future Task?} } \]

GURF is specialized under BM; it is not a second competing general mathematics.

8. Role–Carrier Separation

Status: Core BM firewall

A native mathematical object and the BM role occupied by that object are distinct.

\[ \boxed{x\models_C\rho} \]

means that mathematical object \(x\) occupies role \(\rho\) in Configuration \(C\).

One object may simultaneously occupy several roles:

\[ z\models_C \mathrm{Leaf} \land \mathrm{Response} \land \mathrm{Root}_{B_r}. \]
A role name creates no property beyond the formal conditions defining that role.

9. Problem Scope

Status: Core BM problem specification

The problem scope \[ \mathfrak S_P \] declares the mathematical obligations the current analysis claims to preserve, solve, compare, certify, or continue.

Scope is claim-relative. A present-value problem, one-step continuation problem, finite-horizon problem, and infinite-horizon problem may require different mathematics.

Problem scope cannot be reverse-engineered solely to excuse a favored representation.

10. Obligation Family

Status: Core BM scope structure

Let \(\mathscr T_P\) denote the terminal obligations explicitly claimed by problem \(P\). The active obligation family is their mathematical dependency closure:

\[ \boxed{ \mathscr Q_P = \operatorname{ReqCl}_{\mathfrak D_C} (\mathscr T_P). } \]

Obligations may be functions, predicates, relations, PDE conditions, stochastic transition requirements, convergence statements, witness conditions, receiver requirements, or other native mathematical objects.

11. Branch

Status: Core BM structural role

A Branch is a mathematically distinct focus participating in the declared BM problem.

\[ \boxed{ B= \left( \mathsf S_B, \tau_B, X_B, A_B, \mathcal L_B, \mathcal O_B, \mathcal P_B \right). } \]
\(\mathsf S_B\) Native mathematical sector or structure kind.
\(\tau_B\) Required type information.
\(X_B\) Ambient carrier, state space, or sector-correct analogue.
\(A_B\) Admissible region or admissibility structure.
\(\mathcal L_B\) Native laws, constraints, identities, or invariants.
\(\mathcal O_B\) Native Operations.
\(\mathcal P_B\) Passport / Interface obligations associated with the Branch role.
The seven-field record is an organizational BM specification. It is not a claim that every mathematical object intrinsically has seven ontological components.

12. Branch Information

Status: Core BM interpretation

Branch Information is the distinction structure carried by a Branch's native mathematics.

A distinction matters when collapsing it changes at least one declared law, Operation, Interface, continuation, Passport condition, obstruction, provenance requirement, or receiver obligation.

\[ x\neq_Bx' \]

may denote a distinction recognized by Branch \(B\), but the actual semantics of that distinction come from the native sector.

13. Branch Essentiality

Status: Active BM decomposition criterion

A Branch separation is essential relative to \((P,\mathfrak S_P)\) when every admissible coarsening that removes the distinction destroys at least one required obligation.

In a deterministic common-source case, a separation witness is a required \(T\) for which no \(\widetilde T\) exists satisfying

\[ \boxed{ T = \widetilde T \circ q \circ R_{\mathcal B}. } \]

This blocks arbitrary Branch proliferation.

14. Reduced Branch Decomposition

Status: Active scope-relative BM concept

A lawful Branch decomposition is reduced relative to \((P,\mathfrak S_P)\) when no declared admissible Branch-removing coarsening preserves all required mathematics.

Reduced does not imply unique, canonical, minimum-cardinality, or lattice structure.

15. Operation

Status: Core BM transformation role

An Operation is the general BM role of a typed lawful transformation or native relation.

Deterministic form:

\[ \boxed{ O:D_O\subseteq X\to Y. } \]

Other sectors may use kernels, relations, channels, differential operators, optimization operators, rewrite rules, or another native construction.

16. Interaction

Status: Core BM joint-participation role

An Interaction is an Operation or native mathematical relation carrying a declared joint-participation role among two or more Branch roles.

\[ \boxed{ I: D_I \subseteq A_{B_1}\times\cdots\times A_{B_n} \to Z_I } \]

is the deterministic multi-input case.

  • Interaction is not a second species of underlying map.
  • Product notation does not imply independence.
  • Formal writability does not imply domain admissibility.

17. Interaction Non-Inheritance

Status: Core BM firewall
\[ \boxed{ \text{input structure} \not\Rightarrow \text{output structure}. } \]

Topology, metric, algebra, symmetry, conservation, gauge structure, probability semantics, or any other structure transfers only through an explicit induced structure, preservation theorem, quotient, restriction, transport, completion, or other lawful construction.

18. Leaf

Status: Core BM provenance role

A Leaf is an identified derived result retained for later mathematical use.

\[ z=I(x_1,\ldots,x_n), \qquad \boxed{L=\ell(z)}. \]

The extraction \(\ell\) may be the identity.

  • A Leaf is not automatically a Branch.
  • A Leaf is not automatically a Root.
  • Not every intermediate symbol is a Leaf.

19. Derivational Provenance

Status: Core BM context structure
\[ \boxed{ \Pi^{\mathrm{der}} = \text{derivational provenance}. } \]

Derivational provenance records how a mathematical result was obtained, certified, or derived. Multiple lawful derivations may exist.

Full derivation history need not be copied into every downstream object, but sufficient provenance must remain recoverable when validity depends on it.

20. State / History Context

Status: Core BM continuation structure
\[ \boxed{ H = \text{state/history context}. } \]

State/history context is information about the actual mathematical state or path that future evolution may require.

It is distinct from derivational provenance.

21. Contract

Status: Optional BM obligation-schema layer

A Contract is a reusable typed schema of obligations for a mathematical role.

\[ \boxed{ \mathcal C^\rho = (\Sigma^\rho,\Phi^\rho). } \]

\(\Sigma^\rho\) specifies typed slots or parameters and \(\Phi^\rho\) the obligation templates.

A problem that needs no reusable schema may use an instantiated Passport directly.

22. Passport

Status: Core BM obligation structure

A Passport is the actual instantiated typed obligation family operative in a particular BM role or transition.

\[ \boxed{ \mathcal P^\rho_{\theta,c} = \operatorname{Inst}_{\theta,c} (\mathcal C^\rho). } \]

A Passport may include admissibility, structure, law/regime, witness, coupling, continuation, approximation, reconstruction, receiver, or conservative obligations.

Passport content is mathematical obligation data, not arbitrary metadata.

23. Passport Applicability

Status: Core Passport firewall

A Passport has an applicability domain \(D_{\mathcal P}\).

\[ \operatorname{Acc}(\mathcal P) \subseteq D_{\mathcal P}. \]
\(x\notin D_{\mathcal P}\) Passport is not applicable.
\(x\in D_{\mathcal P}\setminus\operatorname{Acc}(\mathcal P)\) Passport applies but rejects.
\(x\in\operatorname{Acc}(\mathcal P)\) Passport accepts.
\[ \boxed{ \text{not applicable} \neq \text{applicable but false}. } \]

24. Passport Equivalence

Status: Scope-dependent Passport comparison

Two Passports are semantically equivalent when they induce the same acceptance semantics in all relevant contexts.

\[ \boxed{ \mathcal P_1 \equiv \mathcal P_2 } \]

means that their applicable acceptance sets coincide under the declared comparison semantics.

25. Passport Strength

Status: Active order concept

In acceptance-set semantics,

\[ \operatorname{Acc}(\mathcal P_2;c) \subseteq \operatorname{Acc}(\mathcal P_1;c) \]

means \(\mathcal P_2\) is at least as restrictive as \(\mathcal P_1\) in context \(c\).

26. Interface

Status: Core BM connector role

An Interface is a mathematically specified mechanism through which distinct structures communicate, compare, transport, constrain one another, or satisfy shared boundary conditions.

Interfaces may be maps, relations, spans, correspondences, projections, embeddings, discretizations, transport laws, boundary objects, or other sector-correct constructions.

\[ \boxed{ \text{Interface} \not\Rightarrow \text{automatic preservation}. } \]

27. Typed Path

Status: Active BM composition concept

A Typed Path is a sequence of Operations whose domains, codomains, Interfaces, types, and applicable obligations match at every stage.

\[ X_0 \xrightarrow{F_1} X_1 \xrightarrow{F_2} \cdots \xrightarrow{F_n} X_n. \]

28. Composition

Status: Standard mathematics under BM admissibility

For deterministic partial maps

\[ F:D_F\subseteq X\to Y, \qquad G:D_G\subseteq Y\to Z, \]

the true composite domain is

\[ \boxed{ D_{G\circ F} = \{x\in D_F:F(x)\in D_G\}. } \]

Other sectors use their native composition laws.

29. Configuration

Status: Core BM specification structure

A Configuration is the coordinated specification of the active mathematical objects, BM roles, Branches, Operations, Interactions, Interfaces, Passports, law/regime data, provenance, and semantic dependencies of a declared BM problem.

A Configuration is the natural location for BM coordination; it is not a mysterious new native mathematical substance.

30. Well-Formed Configuration

Status: Core Configuration status
\[ \boxed{ \mathrm{WF}(C) } \]

means that the Configuration is type-correct and semantically well-formed relative to its declared native sectors and Interfaces.

Well-formedness does not imply existence of a solution or global realization.

31. Local Admissibility

Status: Core realization status

Relative to declared local regions \(\mathcal U=\{U_i\}\), a Configuration is locally admissible when

\[ \boxed{ \mathfrak F(U_i;C,c) \neq \varnothing \qquad \forall U_i\in\mathcal U. } \]
Local admissibility is cover-relative and does not imply global realizability.

32. Global Realizability

Status: Core semantic realization status
\[ \boxed{ \mathrm{GR}(C;c) \iff \mathfrak F(C;c) \neq \varnothing. } \]

Global realizability is an existence statement. It does not select a particular realization.

33. Semantic Dependency Structure

Status: Core BM dependency structure
\[ \boxed{ \mathfrak D_C } \]

is the semantic dependency/incidence structure of Configuration \(C\). It may be represented by a graph, DAG, hypergraph, factor graph, category, variable-constraint relation, operator network, or another suitable native object.

BM does not assume that ordinary graph ancestry captures every dependency.

34. Network

Status: Core BM organizational structure

A Network is a chosen mathematical representation of the semantic dependency structure \(\mathfrak D_C\).

Networks may contain branching, merging, shared variables, hyperedges, feedback, cycles, local Trees, Interfaces, and global constraints.

A Network describes dependency structure; it is not automatically a lawful realization.

35. Realization Family

Status: Core BM semantic construction
\[ \boxed{ \mathfrak F(C;c) } \]

is the family of all lawful global realizations of Configuration \(C\) under context \(c\).

A realization must satisfy every applicable Branch law, true Operation domain, Interaction domain, Interface, Passport, law/regime condition, coupling condition, coherence requirement, global constraint, and feedback closure.

36. Tree

Status: Core BM realized-configuration role

A Tree is a Configuration together with a selected lawful realization and the context required to interpret that realization.

\[ \boxed{ T= (C,\xi,\Pi,\omega,\Lambda), \qquad \xi\in\mathfrak F(C;c). } \]
  • A BM Tree need not be a graph-theoretic tree.
  • A Network drawing without a lawful realization is not yet a Tree.
  • Tree is a BM role, not a new native mathematical species.

37. Response

Status: Core BM output role; central GURF role

A Response is the typed output of a declared BM computation under the active native semantics.

\[ \boxed{ T\xrightarrow{\mathcal E}Y. } \]

A Response may be deterministic, set-valued, relational, stochastic, operator-valued, law-valued, geometric, or otherwise sector-correct.

38. Export

Status: Core BM receiver-directed operation

An Export prepares a Response for a specified downstream receiver.

\[ \boxed{ E_r: D_{E_r} \subseteq \mathcal Y_T \to \mathcal R_r, \qquad r=E_r(Y). } \]

In deterministic exact semantics, receiver obligation \(T_r\) is preserved when

\[ \boxed{ T_r = \widetilde T_r \circ E_r. } \]

39. Root

Status: Core BM receiver-relative role

A Root is a receiver-admissible exported result.

\[ \boxed{ r\text{ is a Root for }B_r \iff r\in \operatorname{Acc} (\mathcal P_R^{B_r}). } \]

Root Passport applicability is checked before Root acceptance.

  • Roothood is receiver-relative.
  • Roothood is not transitive across arbitrary later receivers.
  • Root does not imply recurrence, convergence, uniqueness, or conservation.

40. Re-entry

Status: Core BM recursive-participation mechanism

Re-entry is the lawful use of an accepted export as input to later mathematics.

\[ \boxed{ \text{Tree} \to \text{Response} \to \text{Export} \to \text{Root} \to \text{receiver} \to \text{later Configuration}. } \]

Re-entry may require revalidation, re-Passporting, law updates, repair, or downstream recomputation.

41. Rooting

Status: Candidate specialized BM attachment structure

Rooting is candidate BM mathematics for an explicitly defined lawful attachment of a Root to a receiving mathematical structure.

\[ \mathcal A: D_{\mathcal A} \subseteq A_{\mathrm{attach}} \times A_R(B') \to X'. \]
Root reuse alone does not establish Rooting.

42. Rebranching

Status: Candidate BM structure

Rebranching is candidate language for the case in which accepted Rooting or re-entry initiates a new distinct Branch development.

\[ \boxed{ \text{Rooting} \not\Rightarrow \text{Rebranching}. } \]

43. Seed

Status: Candidate BM generative role

A Seed is candidate BM terminology for a declared generative process that remains in a non-exporting phase until a mathematically specified export condition is reached.

\[ S_0 \xrightarrow{G} S_1 \xrightarrow{G} \cdots \xrightarrow{\text{export condition}} R. \]

A Seed requires a state space, admissibility, update rule, export condition, and export map.

Initial data is not automatically a Seed.

44. Law Space

Status: Active specialized BM structure

A Law Space \(\mathscr L\) is a mathematical carrier of possible laws, regimes, constitutive families, parameter families, or rule contexts when the active law itself is mathematically relevant.

\[ \lambda\in\mathscr L, \qquad \mathcal L_\lambda = \text{active law at }\lambda. \]
Law Space is not required when the governing law is fixed and mathematically inactive as a separate distinction.

45. Law Assignment

Status: Active specialized BM relation
\[ \boxed{ \Lambda: \Omega_{\mathscr L} \rightrightarrows \mathscr L. } \]

assigns one or more admissible laws to Configurations on which the law-assignment question is meaningful.

If \[ |\Lambda(C)|>1, \] BM does not silently choose one law unless an independent lawful selector is supplied.

46. Representation

Status: Standard mathematics used throughout BM/GURF

A Representation is a mathematical map or sector-correct transformation through which a richer state or structure is expressed in another mathematical form.

Deterministic Set-like case:

\[ F:X\to Y. \]

BM audits which distinctions are merged and whether downstream obligations survive.

47. Fibre

Status: Standard mathematical construction

For a deterministic map \(F:X\to Y\), the fibre over \(y\in F(X)\) is

\[ \boxed{ F^{-1}(y) = \{x\in X:F(x)=y\}. } \]

48. Exact Sufficiency

Status: Exact deterministic factorization concept

Representation \(R:X\to Y\) is exactly sufficient for deterministic obligation \(T:X\to W\) when

\[ \boxed{ T = \widetilde T \circ R } \]

for some \[ \widetilde T:R(X)\to W. \]

Equivalently:

\[ R(x)=R(x') \Longrightarrow T(x)=T(x'). \]
This Set-like criterion is not universal across other semantic sectors.

49. Approximate Sufficiency

Status: Sector-dependent quantitative concept

Approximate sufficiency replaces exact preservation by a declared quantitative error, divergence, risk, norm, metric, operational tolerance, or another native approximation structure.

The symbol \(x\approx y\) has no BM meaning without declared approximation semantics.

50. Structured Quotient

Status: Standard quotient mathematics under BM audit

A set-level quotient is structured only when the native Operations or relations descend lawfully.

For finitary operation \(\sigma\), a congruence requires

\[ x_i\sim y_i \ \forall i \Longrightarrow \boxed{ \sigma(x_1,\ldots,x_n) \sim \sigma(y_1,\ldots,y_n). } \]

51. Dynamic Closure

Status: Core dynamic-sufficiency firewall

Let

\[ \Phi:A\to A, \qquad R:A\to Y, \qquad Y_R=R(A). \]

Exact Dynamic Closure holds iff there exists

\[ \boxed{ \widetilde\Phi: Y_R \to Y_R } \]

such that

\[ \boxed{ R\circ\Phi = \widetilde\Phi \circ R. } \]
Static sufficiency does not imply Dynamic Closure.

52. Convergence Structure

Status: Core semantic firewall

BM has no universal convergence relation.

\[ \boxed{ x_n\to x } \]

is valid only after the native sector declares the topology, metric, norm, weak topology, operator topology, order convergence, probabilistic convergence, or other structure giving meaning to \(\to\).

53. Approximation Structure

Status: Core semantic firewall

Approximation requires a declared comparison object and error semantics.

\[ d_Q(q_1(x),q_2(y)) \le \varepsilon \]

is meaningful only when \(Q\), \(d_Q\), units or normalization, and tolerance interpretation are specified.

54. Coherence

Status: Core BM comparison concept

BM coherence has three distinct components.

Domain coherence

\[ x\in D_{P_1}\cap D_{P_2}. \]

Legitimate comparison

\[ q_1:Y_1\to Q, \qquad q_2:Y_2\to Q. \]

Agreement

\[ \boxed{ q_1P_1(x) = q_2P_2(x). } \]

Approximate coherence may use a declared error structure.

55. Higher Coherence

Status: Active BM local-to-global direction
\[ \boxed{ \text{pairwise coherence} \not\Rightarrow \text{global coherence}. } \]

Higher-order consistency may require CSP, sheaf/descent, category, homotopy, cohomological, algebraic, analytic, or other native mathematics.

No single higher-coherence formalism is universal in BM.

56. Witness Scope

Status: Core quantifier-scope firewall

BM distinguishes local, independent, shared, reusable, and coupled witnesses.

Independent:

\[ \exists w_1\,\varphi_1(w_1), \qquad \exists w_2\,\varphi_2(w_2). \]

Shared:

\[ \exists w\, [ \varphi_1(w) \land \varphi_2(w) ]. \]

57. Coupling

Status: Active BM coupling concept

Coupled witnesses may be represented by an explicit relation \(K\):

\[ \boxed{ \exists w_1\exists w_2: R_1(x,w_1) \land K(w_1,w_2) \land R_2(x,w_2). } \]

In finite relational sectors this is ordinary conjunctive-query / CSP mathematics.

58. Feedback Realization

Status: Core BM realization concept

A cycle in a Network does not itself define a feedback solution.

\[ \boxed{ \mathfrak F(C) } \]

denotes the native realization family of the feedback component.

A fixed point

\[ x=\Theta(x) \]

is one possible feedback semantics, not a universal one.

Multiple realizations require preserved multiplicity or an independent lawful selection rule.

59. Finite Tree Gluing

Status: Classical tree-gluing / CSP theorem used by BM

Let \(H=(V,E)\) be a finite rooted tree, let each local realization set \(F_v\) be nonempty, and for each oriented edge \(u\to v\) let

\[ C_{uv} \subseteq F_u\times F_v \]

be the complete compatibility relation across that edge.

Assume the global realization set factors exactly as

\[ \mathfrak F_H = \left\{ (x_v): x_v\in F_v,\; (x_u,x_v)\in C_{uv} \ \forall uv\in E \right\}. \]

If every parent state extends across every child edge,

\[ \forall(u\to v)\in E,\; \forall x_u\in F_u,\; \exists x_v\in F_v: (x_u,x_v)\in C_{uv}, \]

then

\[ \boxed{ \mathfrak F_H \neq \varnothing. } \]

BM's obligation is to prove that the actual problem has been faithfully encoded into the \(F_v\) and \(C_{uv}\).

60. Obstruction

Status: Core BM failure certificate

An Obstruction is a mathematical certificate that a required lawful structure cannot exist.

\[ \boxed{ \text{failure to find} \neq \text{proof of obstruction}. } \]

61. Defect

Status: Active BM failure object

A Defect is a mathematical object tied to an actual failed requirement \(\Psi\).

\[ \boxed{ \operatorname{Def}_\Psi. } \]

Its type may be a set, relation, residual, norm, rank, operator, geometric object, cohomology class, or another native construction.

62. Defect Calculus

Status: Active domain-independent BM mathematics

Defect Calculus is BM's domain-independent direction for representing, comparing, localizing, refining, coarsening, and repairing failures of declared mathematical conditions.

It is not one universal scalar defect number.

63. Task-Labelled Fibre

Status: GURF-linked Defect-Calculus sector

For carrier \(C:X\to Y\) and Task \(T:X\to Z\), define

\[ F_C(c) = C^{-1}(c), \]
\[ \boxed{ \mathfrak D_T(C;c) = \left( F_C(c), T|_{F_C(c)} \right). } \]

Exact refinement:

\[ \boxed{ F_{(C,W)}(c,w) = F_C(c) \cap W^{-1}(w). } \]

Deterministic coarsening:

\[ \boxed{ F_{P\circ C}(d) = \bigcup_{c:P(c)=d} F_C(c). } \]

64. Repair

Status: Active BM repair structure

A Repair is an admissible modification that restores a failed mathematical condition while respecting declared preservation obligations.

\[ \boxed{ \mathscr R_{\mathrm{adm}} \subseteq \mathsf{Conf} \times \mathsf{Conf}. } \]

\(C'\) is an admissible repair of \(C\) only if \[ (C,C')\in\mathscr R_{\mathrm{adm}}. \]

Repair invalidates affected certification throughout the dependency closure

\[ \boxed{ \operatorname{Cl}_{\mathfrak D_C}(S) } \]

unless recomputation or an invariance theorem protects the result.

65. Minimal Repair

Status: Active only after a repair order/cost is declared

A Minimal Repair is a successful admissible repair that is minimal relative to an explicitly declared cost, preorder, metric, inclusion order, or other comparison criterion.

No universal BM notion of repair minimality exists.

66. Refinement

Status: Active BM comparison structure

Refinement is defined only after comparison semantics are declared.

Common-source deterministic case:

\[ R_1:X_P\to Y_1, \qquad R_2:X_P\to Y_2, \]
\[ \boxed{ R_1 = A_{21} \circ R_2. } \]

This may witness

\[ \mathcal B_1 \preceq_{P,\mathcal T} \mathcal B_2. \]

With fixed comparison data, refinement is at least a preorder.

A lattice is asserted only when meets and joins actually exist.

67. Information Distinction

Status: Core BM information interpretation

BM treats information structurally through distinctions represented by the active mathematics.

Different information types are not automatically interchangeable.

\[ F(x_1)=F(x_2), \qquad x_1\neq x_2 \]

means that the representation \(F\) no longer distinguishes the two source states. It does not by itself prove total-system destruction.

68. Information Persistence

Status: Exact deterministic form; sector-specific generalizations required

If BM asserts total-system persistence of information type \(\mathcal I\) in an exact deterministic model, a larger carrier may be required:

\[ \widehat F:X\to Y\times H, \]
\[ \boxed{ \widehat F(x_1) = \widehat F(x_2) \Longrightarrow x_1\sim_{\mathcal I}x_2. } \]
This injectivity-style criterion is not the universal definition of information preservation in stochastic, relational, quantum, or approximate sectors.

69. Probability Semantics

Status: Native mathematics permitted inside BM

BM may contain probability spaces, Markov kernels, stochastic processes, and statistical models as native Branch mathematics.

\[ \boxed{ \text{probability mathematics} \neq \text{mandatory probabilistic ontology}. } \]

For Markov kernel \(K\), use the expectation operator

\[ \boxed{ (K\varphi)(x) = \int_Y \varphi(y)\, K(x,dy). } \]

This notation does not presuppose an adjoint structure.

70. Selection Rule

Status: Core non-uniqueness firewall

Existence of multiple admissible objects does not define a preferred one.

\[ \boxed{ \exists x\in S \not\Rightarrow \text{canonical }x. } \]

If downstream mathematics requires one realization, law, repair, minimizer, witness, or Root among several, BM requires either preservation of the multiplicity or an independent lawful selection rule.

71. Certification Status

Status: Core semantic / epistemic distinction

Semantic truth and current certification are distinct.

For realizability:

\[ \mathfrak F(C;c)\neq\varnothing \quad\text{or}\quad \mathfrak F(C;c)=\varnothing \]

while available evidence may be:

Certified realizable Certified obstructed Unresolved

\[ \boxed{ \text{failure to certify} \neq \text{certification of failure}. } \]

72. Computability Status

Status: Core computational firewall
\[ \boxed{ \text{existence} \neq \text{decidability} \neq \text{effective construction} \neq \text{efficient construction}. } \]

Complexity claims require an explicit computational model, encoding, and resource measure.

73. Existing-Mathematics Reduction Rule

Status: Core rigor / prior-art rule

Before introducing specialized BM mathematics, test whether an established mathematical theory already solves the same subproblem.

\[ \boxed{ \text{known mathematics} \Rightarrow \text{use and credit it rather than rename it}. } \]

If only part of a BM construction reduces, the known part is credited and the residual becomes the actual research target.

74. Task

Status: Canonical GURF concept

A Task is a declared mathematical quantity, decision, property, control requirement, response requirement, or future-use requirement whose determination matters to the problem.

Deterministic form:

\[ T:X\to W. \]
Sufficiency for one Task does not imply sufficiency for another.

75. Observation

Status: Canonical GURF concept

An Observation is a mathematically declared representation of the underlying state available to a response system, analyst, sensor, controller, inference process, or later calculation.

Observation equivalence does not imply underlying physical identity.

76. Intervention

Status: Canonical GURF response operation

An Intervention is a declared operation that changes the modeled state, response conditions, active law, observation process, or continuation structure.

Intervention semantics are domain-specific; causal interpretation is not inferred solely from the word Intervention.

77. Continuation

Status: Canonical GURF response concept

Continuation asks whether retained mathematical information is sufficient to determine, constrain, or certify the required future response.

Static Task sufficiency is weaker than Dynamic Closure.

78. Completion Fibre

Status: Canonical GURF exact-set construction

Given compatible Passport observations \[ b_\alpha:X\to Y_\alpha, \] the Completion Fibre is

\[ \boxed{ \mathfrak C_A(\ell) = \bigcap_{\alpha\in A} b_\alpha^{-1}(\ell_\alpha). } \]
No probability distribution over the fibre is implied.

79. Response Ambiguity Set

Status: Canonical GURF response concept

For response or Task map \(T\) and a completion fibre \(\mathfrak C_A(\ell)\), the response ambiguity set is

\[ \boxed{ \mathcal A_T(\ell) = T(\mathfrak C_A(\ell)). } \]

A singleton ambiguity set represents exact determination in the declared deterministic model.

80. SOE

Status: Active GURF extension

SOE is the GURF extension governing operation-level response structure, including typed Operation contracts, admissibility, order, error obligations, failure conditions, provenance, and permitted downstream Interfaces.

SOE uses BM Operation mathematics while specializing it for response systems.

81. ACE

Status: Active GURF extension

ACE is the active GURF extension for admissibility, constraints, compatibility, and response conditions whose identity depends essentially on the response system being modeled.

Domain-independent constraint mathematics remains BM-owned.

82. IRE

Status: Active GURF extension

IRE is the GURF extension concerned with inverse, recovery, reconstruction, ambiguity, and response-relevant information requirements.

83. UKE

Status: Active GURF extension

UKE is the active GURF extension for response problems whose uncertainty or knowledge state requires explicit mathematical treatment beyond exact deterministic representation.

UKE does not authorize probability as a universal ontology.

84. GRDE

Status: Frozen GURF extension

GRDE is retained as a frozen GURF response extension. Its frozen status means it remains part of the architecture but is not presently being expanded as active canonical mathematics.

85. HDE

Status: Active GURF extension

HDE is the active GURF extension for response systems whose lawful behavior depends essentially on history, hidden state, delayed information, or other continuation-relevant context.

86. GHSE

Status: Active GURF extension

GHSE studies response systems whose lawful behavior depends on joining, attachment, holding, persistence, release, or transition among coupled components.

Arbitrary attachment or joining is not automatically admissible.

87. HEC

Status: Formal recovery required

HEC is a retained BM project-history name for a domain-independent mathematical direction whose complete canonical calculus has not yet been recovered in the current formal corpus.

HEC may not supply theorem hypotheses, conclusions, Operations, axioms, or deductions merely from its name or historical placement. Its defining mathematics must be recovered or reformalized first.

88. HEC-S

Status: Formal recovery required

HEC-S is a retained project-history name for an internal HEC sector.

Since HEC itself currently requires formal recovery, HEC-S does not independently supply canonical mathematical laws or theorems.

89. Attachment Complex

Status: BM/GURF bridge and candidate infrastructure

An Attachment Complex is a structured record of proposed attachments when candidate sites, compatibility data, holding conditions, release rules, or response semantics must be coordinated.

Naming an Attachment Complex does not prove that an admissible attachment exists.

90. Sector-Semantics Firewall

Status: Core BM/GURF rigor rule
\[ \boxed{ \text{function} \neq \text{Markov kernel} \neq \text{relation} \neq \text{quantum channel}. } \]

Deterministic formulas are not silently reused in stochastic, relational, quantum, approximate, or other sectors.

91. Portability Firewall

Status: Canonical BM/GURF ownership rule

Domain-independent mathematical kernels belong to BM. A construction remains GURF-specific when its identity depends essentially on response semantics.

\[ \boxed{ \text{domain-independent mathematics} \longrightarrow \mathrm{BM} } \]
\[ \boxed{ \text{essential response identity} \longrightarrow \mathrm{GURF}. } \]

92. BM / GURF Specialization

Status: Canonical architecture relation

BM is the broader mathematical metaframework. GURF is a response-specialized framework under BM governance.

\[ \boxed{ \mathrm{GURF} \hookrightarrow \mathrm{BM} \quad \text{as a response-specialized framework}. } \]
The arrow denotes specialization, not literal set containment of mathematical objects.

93. Governing Definition Rule

Status: Core rigor rule
\[ \boxed{ \text{definition} \neq \text{theorem} \neq \text{model} \neq \text{realization claim} \neq \text{novelty claim}. } \]

A definition establishes terminology and mathematical obligations. Existence, uniqueness, proof, computation, physical interpretation, empirical validity, and historical novelty require separate arguments.

Role-erasure audit

If a claimed theorem loses its mathematical content when BM role words such as Branch, Leaf, Tree, Root, Passport, or Seed are erased, then the theorem has not yet been mathematically justified.

No duplicate-theory rule

If established mathematics already completely realizes a proposed BM subconstruction under the claimed scope, BM uses and credits that mathematics rather than renaming it as a separate new theory.
